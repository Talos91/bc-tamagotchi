# Voxel character kit

Generated by `tools/blender/bc_chars.py` (Blender 5.2, headless). Never edit the GLBs by hand: change the script and
re-run. The script imports `tools/blender/bc_kit.py` for the voxel scale, palette, greedy meshing, the jitter/seam
texture and the material builder, so characters and venue share one surface finish.

## Build

From the repo root (about a minute for everything, including the review render):

```
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python tools/blender/bc_chars.py
```

| Flag (after `--`) | Effect |
|---|---|
| `--only tong,nam` | re-export just those presets; leaves the manifest, libraries and .blend alone |
| `--no-blend` | skip `blender/BlackCabinChars.blend` and the render |
| `--no-render` | write the .blend, skip `docs/art/chars-showcase.png` |
| `--review-only` | rebuild only the .blend and the render |

Then refresh Godot, from `game/`:

```
godot --headless --path . --import
godot --headless --path . --script res://assets/chars/build_showcase.gd
godot --path . --script res://assets/chars/capture_showcase.gd
```

The capture needs a GPU window. It writes `docs/art/chars-showcase-godot.png` and prints every AnimationPlayer's
animation list for one preset and the three part libraries (all 13 animations on an 8-bone Skeleton3D, checked
2026-10-27).

**Review in Blender:** `blender/BlackCabinChars.blend` has one collection per row (regulars, staff and house band,
patrons), an "Animations" row with the same patron in every animation at frame 12, and a parts lineup (busts with
every head shape, hair style, face set and head accessory; mannequins with every top, bottom, shoe, body type and
prop). Material Preview, warm key, red fill, warm rim.

## Scale (v2, renders 05/06 parity)

One voxel = 5 cm; the venue draws every preset at `PatronFigure.FIG_SCALE` 0.75 (1.1-1.2 m on screen, as the
figures in renders 05/06). Measurements, the pose plan and the review sheets: `docs/art/screens/chars/`. Head
8 W x 7 D x 7 H; with hair it is close to a third of the height and a little narrower than the shoulders.

| Body | Torso (W x D) | Legs (thigh / shin / shoe) | Chest | Arms (upper / fore / hand) | Head top | With hair |
|---|---|---|---|---|---|---|
| `petite` | 8 x 5 | 10 (5 / 3 / 2) | 8 | 4 / 3 / 2 | 27 vox | 28-30 |
| `regular` | 8 x 5 | 11 (6 / 3 / 2) | 9 | 4 / 4 / 2 | 29 vox | 30-31 |
| `broad` | 10 x 6 | 11 | 10 | 5 / 4 / 2 | 30 vox | 31-33 |

Seated poses put the thigh undersides at `seat_vox` 9 (0.45 m at scale 1), so with the figure at FIG_SCALE the root
goes `SEAT_H * FIG_SCALE` (0.3375 m) below the real seat: cafe chairs and drum stools 0.45 m, bar stools 0.8 m.
Table tops (0.75) and the bar top (1.1) are both 0.30 m above their seats, which is where `sit_drink` and
`sit_talk` rest the forearms.

## Rig

Bones: `root` (floor) -> `hips` -> `spine` -> `head`, `arm_L` -> `forearm_L`, `arm_R` -> `forearm_R`; `hips` ->
`leg_L` -> `shin_L`, `leg_R` -> `shin_R`. Every bone points up with roll 0, so in Godot every bone's rest rotation is
identity: a `BoneAttachment3D` on `head` is upright and faces the character's front. Front is +Z in Godot,
character left is +X. Every voxel is skinned to one bone at weight 1.0 (rigid); hands and held props ride the
forearms, shoes the shins. Animation channels: rotation for every bone, translation for `root` and `hips` only,
linear keys every 3 frames.

13 tops x 5 bottoms x 3 shoes. Tops own the chest and sleeves (bare forearms are skin voxels in the top); bottoms
own the pelvis and legs (bare legs are skin voxels in the bottom). In a preset, overlapping parts are resolved at
build time (later layers win: jacket hem over the belt, glasses over brows); a runtime creator assembling from a
library should avoid the same pairs.

In a library the mesh nodes are named by part id (`hair_bob`, `top_tee`, `eyes_dot`, `hands`, `drink_beer`); in a
preset they are named by slot (`hair`, `top`, ...) and accessories keep their id.

## Preset format

`bc_chars.py` `PRESETS` holds one dict per character, built with `P(...)`:

```python
P("tong", "Tong", "regular", "REG_TONG", "regular", "square", "crop", ("dot", "flat", "smile"),
  "tee", "jeans", "sneakers", ["hat_bucket", "gig_bag", "drink_beer"],
  skin="Skin4", hair="HairBlack", top="Mustard", top_trim="Cream", shoes="Cream", shoes_trim="ColumnWhite")
#  name, display, role, slot id, body, head, hair, (eyes, brows, mouth), top, bottom, shoes, accessories, colours
```

Colour keys are the material slots above, plus `<accessory id>` / `<accessory id>_2` to override a prop's colours.
In `manifest.json` each preset carries `name`, `display`, `role` (`regular`, `staff`, `band`, `patron`), `slot`
(cast bible slot id such as `BAR_1`), `path`, `body`, `parts` (the slot options plus `accessories`), `colours`
(slot -> swatch and hex, only the slots it uses), `height_m` / `height_vox` (top of hair or hat), `head_top_vox`
and `tris`.

## Assembling a custom character at runtime

1. Instance `parts/parts_<body>.glb` for the chosen body type. It already has the Skeleton3D, every part as a
   skinned MeshInstance3D, and the AnimationPlayer.
2. `BCChars.setup_animations(node)` once.
3. `BCChars.show_parts(node, ids)` with one id per slot: `head_<shape>`, `hair_<style>`, `eyes_<v>`,
   `brows_<v>` (omit for `none`), `mouth_<v>`, `top_<style>`, `bottom_<style>`, `shoes_<style>`, `hands`, plus
   accessory ids and `blush` when Warm or above.
4. `BCChars.recolour(node, slot, Color(hex))` per slot: `skin` (also colours bare forearms, legs and hands), `hair`
   (also brows), `top`, `top_trim`, `bottom`, `shoes`, and so on. It replaces matching surfaces with an override
   material, applying the 1.07 factor bc_kit v2 uses to cancel the texture's jitter scale.
5. Expressions: swap `mouth_*` / `eyes_*` / `brows_*` visibility (for example `brows_worried` + `mouth_flat` for
   Meh).
6. Changing body type means instancing the other library and re-applying the same ids and colours.

A library holds all 75 parts at once (about 0.85 MB each); hidden meshes cost no draw calls. If memory matters on
phones, copy the chosen meshes into a lean scene instead: each MeshInstance3D needs its `mesh`, `skin` and
`skeleton` path.

## Replacing the venue's box placeholders

The venue's `PatronFigure` (`game/scenes/venue/patron_figure.tscn`, `game/scripts/venue_patron_figure.gd`) already
loads these presets: **one step, pass the preset name instead of colours**:

```gdscript
figure.set_look({"preset": "patron_05"})   # or "nam", "tong", "jo" ... any manifest.json preset name
figure.play("walk")
```

It instances `res://assets/chars/presets/<name>.glb` under a child `Model`, sets the loop flags, and falls back to the
box figure when the file is missing. Nothing needs rescaling: presets are in metres (1 voxel = 0.05 m), pivot at the
feet, front +Z, the same as the placeholder. `play()` accepts every name in the animation table above (it falls back
to `idle` for unknown ones), so tipsiness and low Vibe are `figure.play(BCChars.anim_for("walk", tipsy, vibe))`.
`move_speed / 1.1` scales the walk as the placeholder expects; for `walk_tipsy` and `walk_merry` divide by their
`root_speed_mps` from the manifest instead. `sit` puts the hips at 0.45 m, the placeholder's `SEAT_H`. The
`HeadTurn` modifier finds the `head` bone by name. For the player's own custom character use a parts library
(previous section) as the `Model` instead of a preset.

## Known gaps

- Raised arms reach above the head (10-row arms against a 7-row head); `dance` and `idle_merry` splay a
  raised arm outward so it clears the hair.
- Seated feet hang a little above the floor at cafe chairs: chibi shins (0.19 m drawn) are shorter than a 0.45 m
  seat. Tables hide it from the game cameras.
- Staff black (Cabin Dark) reads very dark in the red-lit room; the gold trim carries it.
- No turn, emote, wave or high-five yet (GDD 5.3 verbs); no seated variants for Tipsy/Merry ("chin on hand").
- Libraries carry every clip (including tray, pour and band) on every body; trim them when the creator lands.
