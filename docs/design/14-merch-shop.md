## 1. Do versions wipe the character? (checked 2026-11-20 on origin/main 9502c68)
No. The save is `user://save.json` (web: IndexedDB under the project name "Black Cabin Tamagotchi", which no version
changes); `save.gd` migrate() keeps every key, `avatar.gd` normalize() keeps unknown keys and migrates record v1 → v2
(wardrobe kit, creator-fix). `test_merch_profile` "version" loads a save written by 0.4.0 under a bumped version and a
save from a newer build: character, name, created-at and player id stay, and no creator prompt.

What DOES lose a character, and what fixes it now:

| Cause | Before | Now |
|---|---|---|
| A new web address (bc-tamagotchi.vercel.app → blackcabin.app) | separate browser storage: a new character | the player code restores it |
| Safari / Chrome evicting site storage (unused for days, low space) | gone | `navigator.storage.persist()` asked; the code restores it |
| Save lost but the anonymous session kept | gone | the server's character comes back by itself |
| Anonymous session lost (refresh token refused) | new account id | the save's code re-links it by itself |
| The player's own reset (farewell card, Retire) | gone, by design | still gone; pieces and code stay with the account |

## 2. Server (supabase/migrations/20261120000002_player_profile_merch.sql)
- `profiles` (presence v1) gains `personality`, `character_created_at`, `avatar_at`, `build`, `restore_code` (10
  characters, no look-alikes), `restored_from`. `created_at` / `updated_at` were already there.
- `merch_items` — the catalogue (seed `supabase/seed/merch_items.sql`): category, name, sort, `price_coins`,
  `price_thb` (both NULL: money is Daniele's call), `free_pick`, `active`.
- `inventory` — `player_id, item_id, acquired_at, source ('free_pick' now; 'purchase', 'grant' later), price_paid`.
- `bc_settings.shop_free` — one switch ends free picks.
- RLS on all; players select only their own profile and inventory; writes only through `bc_profile_save`,
  `bc_profile_get`, `bc_claim_item`, `bc_profile_restore` (security definer). Restore: 10 tries an hour; the code and
  the pieces move to the new account (one live holder). `bc_delete_me` cascades to inventory.

## 3. Client
- `scripts/merch/player_profile.gd` (autoload PlayerProfile): local first (save `ext.merch`), mirrors the character
  and inventory to the server through Presence's anonymous account; a request only when something changed.
- `scripts/merch/merch.gd`: catalogue `data/merch.json` (generated by `tools/merch_catalog.py`, which also writes the
  seed), runtime voxel pieces on the "head" and "spine" bones, masks hide what they cover, hats use the hair cut at
  the brim when the kit has it. Worn pieces live in the avatar record as `merch` {head, eyes, top, acc}: other players
  see them; clients from before ignore them.
- `scripts/merch/merch_shop.gd`: the shop at the lounge merch stand (pick for free, wear, player code, "Have a
  code?") and the wardrobe at the photo booth ("Merch" button over the creator: owned pieces only).
- Hooks in shared files: `main.gd` (merch stand → shop, booth button), `venue_patron_figure.gd` (adjust + dress),
  `needs.gd` (reset keeps `ext.merch`), `presence_mock.gd` (`extensions`), `project.godot` (autoload, strings_merch).
