## What was wrong
1. **Name field (PC web):** `use_prompt = web and DisplayServer.is_touchscreen_available()`; with
   `pointing/emulate_touch_from_mouse` on, that is true on every web build, so a PC click opened the phone prompt path
   (deferred `release_focus()` + `window.prompt`). Focus left the field the same frame; typing only landed by luck.
   Reproduced in a local web build (focus_entered → focus_exited within 1 ms). Fix: prompt only when CSS
   `(pointer: coarse)`; a prompt answered in < 60 ms (browser blocked it) falls back to typing in the field.
   test_avatar `_pc_name`: web-style click (ScreenTouch + mouse) keeps focus, typed keys land.
2. **Coaster Flip:** the catch window was 15–92 % of the flight and the spin flat from the flick, so the ring lit
   3–5 times a flight for 50–190 ms wherever the stack was. A player tapping 200 ms after it lit caught 0 at every
   stack size (probe); only the frame-perfect test bot caught. Fix: flat at the top of the arc, catchable only in the
   ring (±15 % of the flight), 50 ms input-lag allowance. Threshold and spin numbers unchanged; As built updated in
   `docs/design/10-minigame-next.md`. test_coaster_flip `test_human_player`.
3. **Soi Dash:** road half-width `size.x*0.40*0.66` per lane unit put the side lanes at 0.5 ± 0.53 w (off screen).
   Fix: `road_half() = min(0.42 w, 0.32 h)`; shopfronts just past the kerbs. test_soi_dash `test_bounds` at 5 sizes.
